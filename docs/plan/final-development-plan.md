# 体检预约项目最终版开发计划（冻结版）

> 更新时间：2026-04-02  
> 适用范围：`backend/` + `miniprogram/`（含用户端与管理端）  
> 状态口径：
> - 开发状态：`已完成` / `进行中` / `待开发`
> - 验收状态：`已通过` / `待验证`

---

## 1. 总目标

在现有 Django 后端可运行基础上，完成小程序用户端与小程序管理端的核心业务闭环，实现：

1. 用户端可完成登录、浏览、预约、报告与咨询主链路。
2. 管理端可完成运营后台核心管理（套餐、预约、报告、用户、文章、咨询）。
3. 输出可答辩、可验收、可演示的一体化版本与文档证据。

## 3. 阶段里程碑（最终执行顺序）

## M1（已完成）：底座与 P0 闭环

目标：完成管理端登录、控制台、套餐、预约可用闭环。  
验收标准：`docs/acceptance/p0-checklist.md` 核心项通过。

## M2（已完成，待持续回归）：P1 管理端扩展

目标：完成管理端报告、用户、资料、文章、咨询能力接入。  
验收标准：
- `docs/acceptance/p1-batch2-checklist.md` 通过（文章）
- `docs/acceptance/p1-batch3-checklist.md` 通过（咨询）

## M3（当前主线）：用户端主链路补齐

目标：完成用户端登录与资料、预约主链路、报告文章咨询闭环。  
关键输出：
- 用户认证与登录态稳定（含失效恢复）
- 预约创建/查询/状态一致
- 报告与内容查询可用
- 异常态与空态统一

验收标准：
1. 用户端主链路（登录 -> 套餐 -> 预约 -> 报告/咨询）可一次走通
2. 无阻断问题（白屏/死循环请求/鉴权无法恢复）
3. 关键页面均有空态与错误提示

## M4（收尾）：最终验收与发布材料

目标：形成可答辩版本与完整文档证据。  
关键输出：
- `docs/acceptance/final-checklist.md`
- `docs/acceptance/demo-script.md`
- `docs/acceptance/release-note-v1.md`
- `docs/acceptance/e2e-test-report.md`

验收标准：
1. 演示脚本一次走通
2. P0/P1 无未关闭阻断缺陷
3. 文档可支持他人独立拉起与联调

## 6. 风险与控制

- 风险 1：前后端字段不一致导致反复改动
  - 控制：持续同步 `docs/api/field-contract-v1.md`
- 风险 2：用户端登录态失效导致流程中断
  - 控制：统一 request 层 401 处理与重登录引导
- 风险 3：功能已开发但验收证据不足
  - 控制：每批次开发后同步验收清单打勾与问题记录

---

## 7. 执行规则（冻结）

1. 每次开发以“可测试最小增量”提交。
2. 每次合入前至少执行一次后端测试：`python manage.py test`。
3. 每个批次必须同步更新对应验收清单。
4. 本文档作为当前版本固定执行计划，后续仅做增量修订，不再重写结构。
