# 课题简介对齐实施计划（固定版）

> 更新时间：2026-04-09
> 对齐依据：`课题简介.md`
> 执行策略：先补课题硬性功能，再做体验优化

---

## 1. 目标与缺口

围绕课题简介，当前剩余重点缺口：

1. 微信端“按分类展示体检套餐”能力需补齐（分类筛选条、联动查询、空态与回显）。
2. 管理员端“体检报告录入管理”需补齐（不仅列表查看，还要新增/编辑/上传）。
3. 管理员端“用户管理”需补齐管理动作（不仅列表查看）。

---

## 2. 阶段计划

## M1（本周）：微信端套餐分类功能闭环

- 增加套餐列表分类栏（全部 + 分类标签）。
- 支持分类切换与搜索叠加筛选。
- 支持下拉刷新后分类和列表同步更新。

验收标准：
- 用户可按分类稳定浏览套餐。
- 分类切换后列表结果正确。
- 空分类场景有明确提示。

## M2：管理员端报告录入管理闭环

- 优先在管理员网页端（`admin-web`）完善“录入/编辑/上传报告”。
- 管理端小程序保持报告列表查看能力。

验收标准：
- 可录入并编辑报告，用户端可查询到结果。

## M3：管理员端用户管理补齐

- 增加用户查询与状态管理（启用/禁用）。
- 保证禁用用户后登录受限。

验收标准：
- 用户管理具备“查 + 管”能力。

## M4：论文与项目一材料收口

- 更新 `docs/acceptance` 清单打勾结果。
- 产出最终验收、演示脚本、发布说明与测试报告。

---

## 3. 当前执行顺序（固定）

1. 先做 M1：套餐分类功能（微信端）。
2. 再做 M2：报告录入闭环（管理员端）。
3. 再做 M3：用户管理动作补齐（管理员端）。
4. 最后做 M4 文档收口。

---

## 4. 对论文口径说明

- “管理员端主要是服务端”按本项目落地解释为：管理员主要在网页后台（`admin-web`）操作，后端 Django API 提供支撑；管理端小程序作为轻量入口。
- 项目一验收以“主链路可运行 + 关键管理能力可演示 + 清单可打勾”为达标标准。
